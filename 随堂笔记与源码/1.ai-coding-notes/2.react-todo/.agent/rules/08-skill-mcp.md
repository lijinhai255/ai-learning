# Skill 与 MCP 沉淀规范

## 何时沉淀

同一流程出现两次以上，或流程包含容易遗漏的步骤、工具编排和质量门禁时，评估沉淀为项目级 Skill。需要访问外部系统、浏览器、数据库或专用工具时，评估通过 MCP 暴露稳定能力。

## Skill 结构

每个 Skill 至少说明名称、适用场景、输入、前置条件、步骤、输出、失败处理、验证命令和示例。脚本放在 Skill 目录内，优先复用仓库工具；说明与脚本版本同步。Skill 只描述可重复流程，不复制一次性业务细节。

推荐布局如下。

```text
.agent/skills/<skill-name>/
  SKILL.md
  scripts/
  templates/
  fixtures/
```

## MCP 契约

每个 MCP 工具定义清晰的输入 schema、输出 schema、错误语义、超时、重试和副作用等级。读取类工具默认幂等，写入类工具必须要求明确目标和可审计回执。凭据由运行环境注入，工具描述和日志均不得暴露密钥。

## 生命周期

先以文档和脚本验证流程，再抽象 Skill；先以本地适配器验证数据边界，再发布 MCP。每次升级保留兼容说明和回滚方式，废弃工具提供迁移窗口。Skill/MCP 变更需通过最小示例、静态检查和回归测试。

## 知识回流

任务结束时记录可复用的命令、决策、失败模式和验收证据。稳定信息进入规则或 Skill，易变信息留在任务记录。定期清理重复、过期和与实际脚本不一致的文档。
