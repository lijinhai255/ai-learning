# 全流程自动验收

## 验收阶段

自主验收从需求矩阵读取场景，按以下顺序执行并保留结果。

1. 配置检查，确认 Node、pnpm、浏览器和测试服务版本满足项目要求。
2. 静态检查，运行格式化校验、ESLint、CSpell 和 TypeScript。
3. 单元与集成测试，运行 Vitest 全量测试并生成覆盖率趋势。
4. 构建检查，分别构建 React、Vue、NestJS 应用和共享包。
5. 端到端测试，启动隔离服务后运行 Playwright 关键旅程。
6. 产物审阅，检查日志、截图、报告、变更清单和已知风险。

## Playwright 约定

每条关键旅程从独立、可重复的数据状态开始，测试结束后清理创建的数据。使用角色、标签和可访问名称定位；确需 `data-testid` 时保持稳定且说明用途。网络、时间和随机性采用可控 fixture，失败时保留 trace、截图和视频。

## Vitest 约定

测试文件与被测模块就近放置或统一收纳到 `tests/`。共享工厂放入 `packages/test-utils`，每个测试独立初始化和清理。覆盖率报告用于发现未测分支，不以单一百分比替代关键场景验收。

## 证据与门禁

验收报告至少包含提交或工作区标识、环境版本、执行命令、通过数量、失败详情、产物路径和剩余风险。任一硬门禁失败时，任务状态保持待处理，除非用户明确批准带风险交付并记录豁免原因、范围和有效期。

## 回归策略

每次缺陷修复先新增复现测试，再修复实现。跨应用契约变更运行 React、Vue、NestJS 消费方回归。高风险路径设置稳定的烟囱测试，在每次合并和发布前执行。
