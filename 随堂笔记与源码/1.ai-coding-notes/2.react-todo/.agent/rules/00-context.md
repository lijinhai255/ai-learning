# 仓库上下文与规则治理

## 目标

仓库承载一个可持续演进的 React、Vue、NestJS 全栈 monorepo。规则文档描述团队约定和智能体执行协议，代码与脚本负责真正的校验。两者出现偏差时，应先修正规则或脚本，再继续扩展功能。

## 约束边界

- 规则默认作用于整个仓库。子目录可增加更具体的 `AGENTS.md`，作用域更小的约定优先。
- 每个规则文件只负责一个主题，内容应能独立阅读，并在文件头写明适用范围。
- 规则改动需要同步更新索引、相关 Skill 和 CI 检查，避免出现只改文字却未落地的约定。
- 规范中使用的命令、目录和脚本名称应与实际仓库保持一致；目录尚未创建时，可先以规划状态记录。

## 事实记录

每项重要设计决策保留来源和日期。推荐使用 `docs/adr/NNNN-title.md` 记录背景、候选方案、决定、影响和复盘条件。需求、测试、实现和验收证据通过 issue、变更说明或任务日志关联，形成可回溯链路。

## 变更分类

| 类别     | 典型内容                         | 最低验证                     |
| -------- | -------------------------------- | ---------------------------- |
| 文档     | 规则、ADR、README                | Markdown 检查、拼写检查      |
| 共享配置 | ESLint、TSConfig、CSpell、Vitest | 配置加载、全量静态检查       |
| 前端     | React、Vue、UI、路由             | 单元测试、构建、关键路径 E2E |
| 服务端   | NestJS 模块、API、迁移           | 单元测试、集成测试、构建     |
| 跨端契约 | DTO、schema、错误码              | 契约测试、消费者回归         |

## 术语

- **需求条目**：可由一个团队在一个短周期内交付的最小行为单元。
- **验收条件**：描述输入、动作、可观察结果和边界的可执行条件。
- **质量门禁**：合并或发布前必须通过的自动化检查集合。
- **智能体**：执行分析、实现、测试、审查或文档任务的 AI 工作单元。
- **Skill**：封装稳定流程、输入输出和验证方式的可复用能力说明。
- **MCP**：对外部工具或数据源提供结构化能力的协议边界。
