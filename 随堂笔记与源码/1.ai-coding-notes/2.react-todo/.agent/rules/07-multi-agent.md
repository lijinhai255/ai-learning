# 多智能体协作协议

## 角色分工

按任务规模选择角色，默认由一个协调智能体维护主线。

| 角色       | 主要产物                                 |
| ---------- | ---------------------------------------- |
| 需求分析   | 用户场景、范围、验收矩阵、风险清单       |
| 架构设计   | 模块边界、数据流、ADR、接口契约          |
| 前端实现   | React/Vue 组件、交互测试、可访问性证据   |
| 服务端实现 | NestJS 模块、DTO、集成测试、迁移说明     |
| 质量验证   | Vitest、Playwright、Lint、拼写、构建报告 |
| 文档沉淀   | AGENTS、rules、Skill、MCP 契约更新       |

小任务可由同一智能体兼任多个角色，但产物格式保持一致。并行任务数量以依赖和审阅能力为准，推荐一个协调者加二至四个执行者，避免为了并行而拆碎紧密耦合的改动。

## 任务协议

每个子任务开始时声明目标、输入、输出文件、依赖、非目标和验证命令。执行过程中只修改已领取边界；发现需要跨边界变更时，先向协调者发送提案。完成时回报变更摘要、测试结果、剩余风险和可复用经验。

## 协调和合并

协调者负责拆解、分配、依赖排序、冲突裁决和最终验收。共享契约先冻结字段和错误语义，再并行实现消费者。合并前由质量角色运行跨包检查，发现失败时回传最小复现和责任边界，不用猜测覆盖问题。

## 上下文与证据

智能体之间传递短而完整的上下文，优先链接文件、行号、命令和结果。原始日志保留在任务产物中，摘要写入任务记录。规则、凭据、环境文件和用户隐私不得通过消息扩散。

## 停止条件

当验收矩阵全部有证据、质量门禁通过、文档同步完成且无未决高风险事项时，协调者结束任务。外部依赖或用户决策缺失时，报告具体阻塞点和已完成检查。
