# MCP 能力契约

MCP 只承载稳定、可审计的外部能力，不把一次性业务决策埋进工具描述。接入新服务前，先用本地脚本或 Skill 验证输入输出，再实现 MCP 适配器。

## 契约模板

| 字段      | 要求                                             |
| --------- | ------------------------------------------------ |
| 工具名    | 动词开头，表达单一动作                           |
| 输入      | JSON Schema，明确必填、默认值和大小限制          |
| 输出      | 稳定 JSON Schema，区分业务失败和工具失败         |
| 副作用    | `read-only`、`idempotent-write` 或 `destructive` |
| 超时/重试 | 明确上限、退避和不可重试错误                     |
| 凭据      | 由运行环境注入，禁止写入仓库和日志               |
| 审计      | 记录调用者、目标、结果和关联 ID，不记录敏感值    |

## 生命周期

需求阶段定义工具边界；实现阶段先写 fixture 和契约测试；验收阶段运行静态检查、单测和最小集成测试；升级时保留兼容版本和回滚说明。任何写入型工具都要有明确目标和用户可见回执。
