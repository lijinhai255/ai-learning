AI 客服：意图识别 → 分流到三个客服节点

langgraph-demo/src/2.graph-flow/agent2.ts · StateGraph(StateAnnotation)
开始 / 结束 普通节点（处理逻辑） 条件边（意图分流） 模型调用（llm.invoke）

调用流程（一次 invoke 走完的路）

① invoke({ question }) → START → ② recognizeIntent：提示词让模型只回一个意图词，写入 intent → ③ routeByIntent：读 state.intent 决定走哪条分支 → ④ 三个客服节点里只跑其中一个：preSales / afterSales / productInquiry，写入 answer → ⑤ END，返回最终 state

节点（做什么）

节点名类型作用 / 状态读写
recognizeIntent 节点 意图识别，调模型分类，返回 { intent }（读 question，写 intent）
routeByIntent 条件边 不调模型，直接 return state.intent，由映射表决定下一个节点
preSales 节点 售前客服人设：价格、优惠活动、下单流程，返回 { answer }
afterSales 节点 售后客服人设：退换货、物流查询、维修申请，返回 { answer }
productInquiry 节点 产品咨询人设：商品参数、功能、使用方法，返回 { answer }

边（怎么流转）

从 → 到类型触发条件
__start__ → recognizeIntent普通边图启动即进入意图识别
recognizeIntent → routeByIntent条件边识别完立刻按 intent 分流
routeByIntent → preSales条件分支意图 = 售前问题
routeByIntent → afterSales条件分支意图 = 售后问题
routeByIntent → productInquiry条件分支意图 = 产品咨询问题
preSales / afterSales / productInquiry → __end__普通边 ×3三个节点都直连终止，回答完就结束

状态字段（StateAnnotation）

字段类型谁来写入
questionstring外部 invoke() 传入（图入口参数）
intentIntentrecognizeIntent，取值只能是三个意图之一
answerstring三个客服节点里跑到的那个

两点补充说明

  • 意图识别的兜底：没有用 structured output，而是靠提示词 + INTENTS.find(item => text.includes(item)) 做关键词匹配；模型哪怕多说了几个字也能命中，全都没命中时落到默认的「产品咨询问题」，保证 routeByIntent 一定拿得到合法分支。
  • 分支互斥：条件边只命中一条，所以一次调用只会执行一个客服节点；三个节点写的是同一个 answer 字段，所以三条边都直连 __end__ 就够了，不需要再合并。
