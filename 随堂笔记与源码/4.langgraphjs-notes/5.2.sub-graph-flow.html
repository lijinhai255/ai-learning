子图（Sub-graph）流程讲解

LangGraph.js：把一个编译好的图当作另一个图里的「节点」来用（这里是两个子图节点）
src/5.sub-graph/agent.ts

一、整体结构图

这份代码里定义了 两个图：右边是子图 subAgent，左边是主图 agent。主图里有 两个子图节点 subAgent1、subAgent2，它们内部各自手动 `invoke` 了右边同一张子图。

二、调用流程讲解

  1. 先定义子图 subAgent：START → fetchTool → modelNode → END，编译成 subAgent。 它和主图共用同一份 StateAnnotation（字段：url / times / text）。
  2. 主图 agent 复用同一个 fetchTool / modelNode，并加上了两个子图节点 subAgent1、subAgent2。 节点名只是字符串，节点本体是普通函数，不是把编译好的图直接塞进去。
  3. 主图执行 START → fetchTool：抓 baidu，写 text、times+1。
  4. 进入 subAgent1 节点：手动 await subAgent.invoke({ times: 0, url: "https://www.baidu.com" })—— 把子图当函数调用，跑完整条子图流程，拿到输出后 console.log，然后 return {}。
  5. 顺序执行到 subAgent2 节点：与 subAgent1 逻辑完全相同，再次 invoke 子图、再打印、再 return {}。 两者由边连接，所以是先后串行执行，不是并行。
  6. 主图 modelNode → END：读取的仍是主图 fetchTool 写的 text，输出最终结果。
⚠ 需要注意的两点：
① 两个子图节点都以 return {} 结尾，没有把子图结果写回主图状态，子图那一轮的结果只停留在日志里。
② subAgent1 和 subAgent2 的调用完全一样（同一个 url、同样的参数），当前效果上属于重复执行；如果是要演示「多个不同子图」，需要给它们不同的输入。

七、要点补充：子图的两种接法

  • 写法 A（本文件）：子图当工具 ——在节点函数里 await subAgent.invoke(输入)， 手动拿返回值、手动决定写回哪些字段。灵活，但要自己处理状态边界的映射。
  • 写法 B：编译好的图直接当节点 ——.addNode("subAgent", subAgent)， LangGraph 会自动把主图状态喂给子图、再把子图输出合并回主图。这是官方推荐的 native sub-graph 用法，本文件未采用。
  • 两个子图节点是串行的：subAgent1 → subAgent2 是普通边，必须等前一个跑完才跑后一个； 想并行得让它们从同一个节点扇出（__start__ → subAgent1 / subAgent2），或改用 Send。
  • store：两个图 compile({ store }) 都传了 InMemoryStore， 用于跨线程的长期记忆；简单流程里即使暂时不用，也不影响执行。
