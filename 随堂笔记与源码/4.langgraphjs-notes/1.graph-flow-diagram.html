LangGraph 工作流：写笑话 → 判断笑点 → 增强 → 润色

langgraph-demo/src/2.graph-flow/agent.ts · StateGraph(StateAnnotation)
开始 / 结束 普通节点（处理逻辑） 条件边（分支判断） 数据流（状态字段读写）

节点（做什么）

节点名类型作用 / 状态读写
generateJoke 节点 调用模型生成第一版笑话，返回 { joke } 写回状态
checkPunchline 条件边 判断笑话有没有笑点，返回 "Pass" 或 "Fail"，决定走哪条分支
improveJoke 节点 让笑话更有趣，返回 { improveJoke } 写回状态
polishJoke 节点 给笑话加历史典故，读取 state.improvedJoke，返回 { finalJoke }

边（怎么流转）

从 → 到类型触发条件
__start__ → generateJoke普通边图一启动就进入生成节点
generateJoke → checkPunchline条件边生成完立刻判断笑点
checkPunchline → __end__条件分支返回 Pass，笑话够好笑，直接结束
checkPunchline → improveJoke条件分支返回 Fail，进入增强环节
improveJoke → polishJoke普通边增强完再润色
polishJoke → __end__普通边润色完流程结束

状态字段（StateAnnotation）

字段写入方说明
topic—定义了但全程没被使用
jokegenerateJoke第一版笑话（也是增强节点的输入）
improvedJoke—从未被写入
finalJokepolishJoke最终输出

三处与图结构对不上的地方

  • 输入字段错位：generateJoke 里读的是 state.joke，但 joke 正是在这个节点里才被写入的；按注释意图应该读 state.topic。
  • 返回 key 拼写不一致：improveJoke 返回 { improveJoke }，而状态字段叫 improvedJoke，导致这次更新写不进状态（LangGraph 只接受状态里已声明的 key）。
  • 连带读到 undefined：因为上一条，polishJoke 读到的 state.improvedJoke 始终是 undefined，提示词里会拼上 "undefined"。
