analyze → 并行 fetch → 汇总（Map-Reduce）

LangGraph.js 动态并行工作流讲解 · 用 Send 把「一次分析 + N 次抓取 + 一次汇总」组织成并行执行
src/4.simple-agent/agent2.ts

一、整体结构图

整张图是一次「扇出 → 并行 → 汇合」：
① analyze 先问模型要 5 个国内可借鉴网站；
② 条件边函数返回 Send[]，为每个 url 各派发一个 fetchTool 任务，它们在同一个超步里并行执行；
③ 所有 fetch 写回的正文被 reducer 拼进 contents，modelNode 作为同步屏障等它们全部完成后统一汇总。

二、调用流程讲解

  1. START → analyze：把用户主题交给 LLM，要求它只返回一个 JSON 字符串数组（5 个国内网站 URL）。 代码里用 extractUrls() 兜底正则提取，避免模型多说了几句就解析失败。
  2. analyze →（条件边）dispatchFetch：路由函数把 state.urls 逐项 map 成 new Send("fetchTool", { url })。返回几个 Send，就会并起几个 fetch 任务——数量由数据决定，而不是写死的边。
  3. fetchTool × N（并行）：每个任务只拿到自己的 { url }（Send 传进去的局部状态）， 用 fetchTool.invoke() 抓正文，然后返回 { contents: [正文] }。
  4. contents 汇合：N 个任务同时写 contents，因此该字段必须声明 reducer: (a, b) => a.concat(b)，否则并发写同一字段会抛 InvalidUpdateError。
  5. fetchTool → modelNode → END：modelNode 有多个入边，天然充当同步屏障， 等所有 fetch 完成后才执行，读取完整的 contents 生成最终汇总结果。

三、节点表

节点类型职责读 / 写状态
analyze LLM 节点 分析用户主题，整理出 5 个国内可借鉴网站 读 topic → 写 urls
fetchTool 工具节点 并行 × N 抓取单个 url 的网页正文（由 Send 动态派发） 读 url（Send 局部参数） → 写 contents
modelNode LLM 节点 同步屏障 汇总所有抓取内容，产出可借鉴要点 读 topic + contents → 写 report

六、要点补充

  • Send 是什么：它让你在条件边里动态决定「调哪个节点、带什么状态」。返回一个 Send 就派一个任务，返回数组就并行派多个。
  • 与 3.parallel-flow 的区别：那一课是写死的 3 条并行边（固定扇出）；这里用的是 Send，扇出数量由 analyze 的结果决定（动态扇出 / map-reduce）。
  • 为什么 contents 必须配 reducer：同一超步里 N 个 fetch 同时更新同一个字段，LangGraph 默认不允许，必须用 reducer 定义「怎么合并」。
  • 同步屏障：modelNode 有多个上游（N 个 fetch），它会等所有上游都到达才执行，因此能读到合并后的完整 contents。
  • 健壮性：抓取走的是真实外部网络，所以 fetch 加了 15s 超时，fetchToolNode 用 try/catch 保证单个站点失败不影响整体汇总。
