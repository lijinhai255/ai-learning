子图（Sub-graph）流程讲解

LangGraph.js：把一个编译好的图当作另一个图里的「一个节点」来用
src/5.sub-graph/agent.ts

一、整体结构图

这份代码里定义了 两个图：右边是子图 subAgent，左边是主图 agent。主图里的 subAgent 节点内部手动 `invoke` 了右边那张子图。

二、调用流程讲解

  1. 先定义子图 subAgent：START → fetchTool → modelNode → END，编译成 subAgent。 它和主图共用同一份 StateAnnotation（字段：url / times / text）。
  2. 主图 agent 复用同一个 fetchTool / modelNode，并额外加了一个叫 subAgent 的节点。 注意这个节点名只是字符串，节点本身是一个普通函数，不是把编译好的图直接塞进去。
  3. 主图执行：START → fetchTool（抓 baidu，写 text 和 times+1）→ subAgent 节点。
  4. subAgent 节点内部：手动 await subAgent.invoke({ times: 0, url: "https://www.baidu.com" })， 也就是把子图当成一个工具/函数来调用，拿到子图的完整输出后 console.log。
  5. 回到主图 → modelNode → END：主图的 modelNode 读取的是主图 fetchTool 写的 text， 输出最终结果。
⚠ 需要注意的两点（当前写法的行为）：
① subAgent 节点最后 return {}，没有把子图结果写回主图状态，所以子图那一轮的执行结果只停留在日志里，主图后续节点读不到它。
② 子图的输出字段名与主图完全同名（text/times），如果直接把它 merge 回来，会覆盖主图 fetchTool 已写入的 text——这正是「子图当工具」时需要提前设计好字段边界的原因。

七、要点补充：子图的两种接法

  • 写法 A（本文件）：子图当工具 ——在节点函数里 await subAgent.invoke(输入)， 手动拿返回值、手动决定写回哪些字段。灵活，但要自己处理状态边界的映射。
  • 写法 B：编译好的图直接当节点 ——.addNode("subAgent", subAgent)， LangGraph 会自动把主图状态喂给子图、再把子图输出合并回主图（要求状态 schema 兼容）。 这是官方推荐的 native sub-graph 用法，本文件没有采用。
  • 为什么要有子图：把一段独立、可复用的流程（像这里的「抓取 + 分析」）封装成一个图， 既可单独运行调试，又能嵌进更大的流程里复用。
  • store：两个图 compile({ store }) 都传了 InMemoryStore， 用于跨线程的长期记忆；简单流程里即使暂时不用，也不影响执行。
