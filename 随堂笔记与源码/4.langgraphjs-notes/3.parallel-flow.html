并行分支：三个 LLM 节点同时跑，再汇合到 aggregator

langgraph-demo/src/3.parallel-flow/agent.ts · StateGraph(StateAnnotation) · fan-out / fan-in
开始 / 结束 调模型节点（llm.invoke） 合并节点（不调模型） 并行执行区（同一批触发）

调用流程（一次 invoke 走完的路）

① invoke({ topic }) → START → ② callLlm1 / callLlm2 / callLlm3 同时执行（彼此之间没有边，属于同一批）→ ③ 三条边都指向 aggregator，等三个节点全部结束后才轮到它（fan-in 汇合）→ ④ aggregator 把 story / joke / poem 拼成 combinedOutput → ⑤ END，返回最终 state

节点（做什么）

节点名类型作用 / 状态读写
callLlm1并行分支以 topic 为题写笑话，返回 { joke }
callLlm2并行分支以 topic 为题写故事，返回 { story }
callLlm3并行分支以 topic 为题写诗歌，返回 { poem }
aggregator汇合节点不调模型，把三份结果拼成一段文字，返回 { combinedOutput }

边（怎么流转）

从 → 到类型含义
__start__ → callLlm1扇出同一个起点连出三条边 = fan-out，三个节点同时被触发
__start__ → callLlm2扇出
__start__ → callLlm3扇出
callLlm1 → aggregator汇合三个节点都指向同一个下游 = fan-in，aggregator 要等三条入边全部到达才开始
callLlm2 → aggregator汇合
callLlm3 → aggregator汇合
aggregator → __end__普通边合并完直接结束

状态字段（StateAnnotation）

字段写入方说明
topic外部 invoke()三个并行节点的共同输入
joke / story / poemcallLlm1 / 2 / 3各写各的字段，互不干扰
combinedOutputaggregator把上面三个字段拼成最终结果

三点补充说明

  • 并行是真的并行：三个节点之间没有任何边，LangGraph 把它们放进同一批（superstep）执行，所以是三次 llm.invoke 同时发出，总耗时≈最慢的那一个，而不是三个相加。
  • 为什么能各写各的字段：并行节点写的是不同的状态字段，没冲突。如果它们要写同一个字段，就必须给该字段配 reducer（比如累加/合并数组），否则会报并发更新冲突（InvalidUpdateError）。
  • 汇合点是同步屏障：aggregator 有三条入边，三条都到齐才会执行；所以它在里面可以放心直接读 state.joke / story / poem，拿到的一定是最终值。
